# 剧情卡生成提示词（可直接复制粘贴）

**用法**：把下面 `===` 之间的内容整段复制给你的 AI 助手，**同时把 `examples/剧情卡制作指南.md` 一并附上**（或让它自己读仓库里的那个文件），末尾接上你的素材。

**两种用法**：

1. **素材很全**（SillyTavern 剧情卡 / 世界书 / 预设 / 小说片段）→ 用**模板 A**。
2. **只有一段口述的剧情概要** → 用**模板 B**（它会让 AI 先梳理再分配字段）。

**只要剧情、不要角色卡**（房间里已有角色池）→ 改用 [`plot-to-config-prompt.md`](plot-to-config-prompt.md)。

---

## 模板 A · 有素材的完整转换

```
你现在的任务：把用户提供的素材改写成一个 MultiTavern 剧情卡（.anyworld.json）。

【必读】请先完整阅读并严格遵守 examples/剧情卡制作指南.md（本消息附带的说明书）。
它包含全部字段语义、硬性限制、跨字段校验规则与一份完整示例。没有读完不要开始写。

【输出要求】
- 只输出一个合法 JSON 对象。不要 markdown 代码围栏，不要注释，不要在 JSON 前后写任何解释文字。
- 字段按需选用：素材里没有的内容直接省略，不要写 null 或空字符串占位，不要发明字段。
- 严格遵守说明书第十五部分的每一项限制，避开第十四部分的全部常见坑，并逐条核对第一部分的「自检清单」。
- 一个字段都不许超出限制；id 引用必须闭合；布尔值必须是真布尔值。

【内容要求】
- scenario：写清「世界与舞台 / 当前局势 / 玩家方 / 目标与利害 / 关键 NPC / 基调」，可写剧透。
- opening：只在素材里有现成开场文（如 first_mes）时才输出，并确保每个角色都有出场动作。
- guidance：把真相、结局条件、NPC 真实动机、节奏与保密要求都放这里。
- characters：只在素材提供了可扮演的主要人物时输出；每人一条独立能力主线，能支撑多人分头行动。
  剧情关键但不被扮演的 NPC 不要放进 characters。
- 只有剧情真的依赖时间与空间时，才输出 time_config / time_rules / events / regions / items。

【素材】
（把素材粘贴在这里：SillyTavern 剧情卡、世界书、预设，或剧本原文）
```

## 模板 B · 只有一段剧情概要

```
你现在的任务：把用户口述的剧情概要，设计并改写成一个 MultiTavern 剧情卡（.anyworld.json）。

【必读】请先完整阅读并严格遵守 examples/剧情卡制作指南.md（本消息附带的说明书）。
它包含全部字段语义、硬性限制、跨字段校验规则与一份完整示例。没有读完不要开始写。

【第一步：先在内部梳理，不要输出过程】
1. 设定：时代、地点、世界观规则、氛围。
2. 局势：故事开始时正在发生什么，紧张点是什么。
3. 玩家方：几个人、彼此什么关系、有什么能力与资源、共同的对手是谁。
4. 目标与利害：要达成什么、失败会失去什么、有哪些明确的限制与时限。
5. 隐藏真相：真凶/真相是什么、关键物证在哪里、NPC 各自的真实动机。
6. 结构：分几幕、哪些时刻会发生什么、结局有几种。
7. 需要哪些机制：时间（倒计时/日程）、空间（地区/物品/门锁）、插件（可能的真相）。

【第二步：按结论分配字段】
- 设定 / 局势 / 玩家方 / 目标与利害 / 关键 NPC / 基调 → scenario（可写剧透）
- 隐藏真相 / NPC 真实动机 / 节奏 / 边界 → guidance
- 需要玩家分头扮演的主要人物 → characters（各有一条独立能力主线）
- 时间与日程 → time_config + time_rules + events
- 空间与探索 → world + regions + items（注意：这会自动启用严格时间轴，因此必须同时给出 time_config）
- 玩家可提交假设 → plugins.possible_truths

【补全的分寸】
- 可以补合理的细节（人名、地名、氛围、次要 NPC），但核心真相与结局必须以用户给的概要为骨架。
- 用户没提到的部分宁可留白，让 AI 主持人在游戏里自由发挥；不要为了填满结构而编造重要设定。

【输出要求】
- 只输出一个合法 JSON 对象。不要 markdown 代码围栏，不要注释，不要在 JSON 前后写任何解释文字。
- 字段按需选用，没有内容的字段直接省略（**尤其不要用 null 占位**）；严格遵守说明书第十五部分的限制、避开第十四部分的常见坑，并核对第一部分的「自检清单」。

【剧情概要】
（把你的概要粘贴在这里）
```

## 生成之后

1. 把 AI 输出的 JSON 存成 `.json` 文件（建议用有意义的文件名，例如 `银烛庄园.anyworld.json`）。
2. 建房页点「导入配置」加载。**导入是合并**：重复导入同一份文件会叠加 `time_rules` / `events` / `lorebook` / `prompt_blocks` / `regions` / `items` 与插件提问，`characters` 则会被清空重建（细节见指南第十七部分）。
3. 导入后检查角色池至少有一个角色，并在表单里勾选你自己要扮演的角色。
4. 常见报错的定位方法：
   - 提示某个字段超限 → 对照指南第十五部分的速查表；若报错提到 `null`，见指南 14.1。
   - 提示引用了不存在的地区/物品 → 检查 `regions[].items`、`links[].to`、`links[].requires_item`、`events[].region`、`world.start_region` 与 `plugins` 里 `event_name` 的 id 拼写。
   - 提示定时事件需要时钟 → 加上 `time_config.enabled = true`。
   - 提示地区系统需要 strict → 删掉你自己写的 `schedule` 字段，让服务器自动推导。
